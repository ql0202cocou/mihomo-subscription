## [0.6.0] - 2026-09-30

### 变更

- 仓库历史重置：自 0.6.0 起以单个初始提交重新开始，此前的提交、tag 与 GitHub Release 均已删除；
  Docker Hub 上已发布的旧版本镜像不受影响。
- YAML 库由已弃用的 `serde_yaml` 换为其维护中的分支 `serde_norway`（API 与输出一致，订阅内容不变）。
- **升级提示**：生成校验更严格。`RULE-SET` 引用的规则集须存在（本订阅已启用的托管规则集或机场自带
  `rule-providers`）；自定义分组不得与任何节点重名；分组之间不得互相引用成环。这些配置此前能「生成
  成功」但客户端无法加载；升级后会生成失败，公开链接继续下发最后一份合法缓存，请在订阅详情页点「立即刷新」
  查看逐条错误并修正。
- 规则/排序编辑、导入托管规则、重置 token 或公共路径前缀后，改为用缓存中的机场原文离线重跑完整转换
  （含校验与规则集注入），不再在输出上就地修补；编辑不合法时保留上一份合法输出。新增迁移
  `0012_cache_provider_yaml.sql`；升级前生成的缓存在下一次回源拉取后才支持离线重生成。
- 更新订阅时名称去除首尾空白，空名返回 `400`（与创建一致）。
- 保存规则、节点块顺序、分组顺序（`PUT .../rules`、`.../node-section-order`、`.../group-order`）由
  `204` 改为 `200`，响应 `{ regenerate: { status, errors? } }` 说明改动是否已下发到订阅；
  `POST .../rule-sets/import` 响应同样新增 `regenerate` 字段。前端据此提示：已应用、下次刷新后更新，
  或「已保存但未通过校验」并列出逐条错误。
- 前端第三方依赖拆为独立的 react / antd / vendor 分块，发版后浏览器可继续使用缓存。

### 修复

- 导入托管规则后，所服务的订阅含 `RULE-SET` 规则却缺少对应 `rule-providers` 定义，客户端加载失败。
- 规则中写错策略名时，错误配置被直接下发，且在之后生成失败时仍作为兜底缓存持续下发。
- 重置 token 或公共路径前缀后，订阅中的规则集托管链接仍指向旧地址（`404`）。
- 导入托管规则时 policy 为空或含逗号、换行会写入畸形规则行；现返回 `400` 且不写入任何数据。
- 机场返回无法解析的内容（如 base64 节点列表）时，新建与手动生成后状态仍显示 `success`；现记录为
  `provider_parse`。
- 全局节点内容中的名字与节点名不一致（如末尾多了空格）时，输出的节点名对不上、分组引用失效；现以
  节点名为准。
- 分组高级选项中的 `name`/`type`/`proxies` 会覆盖分组自身设置；现忽略这三项。
- 节点/分组的高级选项：输入字段名途经已有字段名时（如已有 `plugin` 时输入 `plugin-opts`）会清空该字段；
  删除一行后嵌套 YAML 编辑器显示别行内容；新增字段只能存为文本。现按行编辑并可选值类型（文本/数字/
  开关/YAML），重名的行标红且不会覆盖已有字段。
- 在规则编辑器中编辑 `RULE-SET` 规则会把对应的托管规则集改为由面板缓存并重新启用；现保留原设置。
- 规则保存失败后界面仍显示未保存的修改，且会在下次保存时一并写入；现回滚到服务端状态。
- 规则有错误时，在「规则」以外的页签点「立即刷新」没有任何提示；现始终提示失败，并指明规则错误数量。
- 规则/排序保存后总是提示「已应用到订阅」，即使新配置未通过校验、订阅实际仍是旧输出。
- 拖拽或删除规则后立刻打开另一条规则编辑，保存返回时会关闭编辑弹窗、丢失输入。
- 连续快速拖拽排序时，请求可能乱序生效，界面也会被较早的结果打回旧顺序或丢掉后一次拖拽；现按顺序
  提交，并以最后一次为准。详情页并发刷新时旧数据也不再覆盖新数据。
- 编辑已有规则时，策略下拉只显示与原值同名的一项（被输入框中的原值过滤）；`IN-TYPE` 下拉同理。
- 规则集更新间隔可输入小数，保存时只提示「HTTP 422」；现只能输入整数。
- 输出预览遇到校验失败只显示「Validation failed」；现逐条列出错误。

### 安全

- 出站拉取（机场订阅、规则集远程镜像）不再读取 `HTTP_PROXY`/`HTTPS_PROXY` 等代理环境变量：代理会
  自行解析域名，绕过 SSRF 的 IP 固定。**升级提示**：此前依赖这些变量经代理拉取机场的部署将改为直连。
- `FETCH_TIMEOUT_SECONDS` 改为整次拉取的总时限（含 DNS 解析与全部重定向）；此前每跳重定向各有一份
  完整超时，DNS 解析不受超时约束。
- 远程规则集开启缓存（由面板代为拉取）时，`url` 在保存时即按与订阅源相同的规则校验：内网/本地地址、
  内嵌凭据、非 http(s) 返回 `400`（此前要到拉取时才以 `ssrf_rejected` 失败）。关闭缓存时 URL 由客户端
  拉取，仍允许局域网地址。

### 文档

- 部署文档补充：主机运行 Mihomo/Clash TUN + fake-ip 时，面板拉取机场会全部被 SSRF 拦截的原因与处理。
- 源码注释中已合并文档（`api-design.md` 等）的引用改指 `architecture.md` 对应章节。

## [0.5.1] - 2026-07-02

### 变更

- 公共订阅端点新增回源刷新下限 `PUBLIC_REFRESH_MIN_SECONDS`（默认 30 秒）：下限内复用最近生成
  缓存，降低公开 token 泄露后的上游拉取放大。

- 客户端 IP 派生默认不再信任 `X-Forwarded-For`（`TRUSTED_PROXY_HOPS=0`），新增
  `TRUSTED_PROXY_CIDRS`；只有 TCP 对端落在显式可信反代网段内时才读取 XFF。
- 管理端状态变更请求必须带同源 `Origin`，并按 `PUBLIC_BASE_URL` 的完整 origin 校验，缺失也
  返回 `403`。
- HTTP trace 不再记录完整 URI，公开订阅/规则集路径中的前缀与 token 替换为占位值。
- 公开规则集托管端点的前缀比较对齐订阅端点的防时序模式。
- 升级 Vite/React 插件消除开发服务器漏洞，CI 与 Docker 前端构建切到 Node 22；升级 anyhow
  清除审计告警；compose 示例显式 `SECURE_COOKIES=true`。

  设计稿细节；恢复「添加规则」手动单条新增（与两个导入入口并列）。

- 安全设计：SSRF 分段封锁（含 IPv6 内嵌 IPv4 绕过）、YAML 解析资源限制、机场 URL 脱敏、
  管理请求体 1MB 上限、公开端点不泄露失败原因。
